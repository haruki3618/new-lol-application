# v6.0（プレイ傾向の診断）

このフォルダは v5.1 に v5.2・v6.0 を適用済みの **完成形** です。`.env` を置いて、次の順に実行してください。

```
npm install                    # 初回のみ
npm test                       # 自動テスト
npm run start:all              # サーバー + クローラー
```

新しい依存パッケージはありません。MongoDB のデータ変更もありません。

## 何ができるか
プロフィール上部の **「プレイ傾向を診断」** ボタン（または `/insights/<puuid>`）で、保存済みの試合からその人の傾向を出します。**Riot API は使いません。**

| 項目 | 内容 |
|---|---|
| 連敗後の勝率 | 1敗後 / 2連敗後 / 3連敗以上 / 勝った直後 / セッションの1試合目。「2連敗以上」はまとめても見る |
| 時間帯別の勝率 | 深夜・朝・昼・夜（**日本時間**、試合の開始時刻） |
| その日の何試合目か | 1〜4試合目・5試合目以降、「4試合目以降」のまとめ |
| チャンピオンプール | 使用上位8体の使用率・勝率、何体で試合の半分を占めるか、ロール別の割合 |
| 気づいたこと | 下記の基準を満たす「はっきり差があるもの」だけを文章にする |

## 「少ない試合数で断定しない」ための基準
- 診断には **30 試合以上** が必要（未満のときは表だけ参考として出し、所見は出さない）。
- 所見にするのは、その区分とそれ以外の試合の勝率に **偶然とは言いにくい差** があるときだけ（2つの割合の z 検定、両側95%）。
  さらに **差が 8 ポイント以上**、**両方とも 15 試合以上** が条件。
- 表には試合数と勝率の **95% の幅**（Wilson 区間）を併記し、10 試合未満の区分は「試合数が少ない」と表示。
- **所見が 0 件でも正しい結果**です（「目立った傾向なし」と表示）。
- 多くの区分を同時に調べるため、偶然の差が混ざることがあります。相関であって原因ではありません（画面にも注記）。

## セッションの数え方
- 前の試合の **終了時刻**（開始 + 試合時間）から **60 分以内** に次の試合が始まっていれば同じセッション。
- リメイク・早期降参（**5分未満**）は除外。
- 対象は新しい順に最大 **500 試合**。キューは画面で切り替え（既定はソロランク）。

## 注意（既知の制限）
- **保存されている試合が連続していないと数え方がずれます**（一部の試合だけを読み込んだ場合など）。連敗やセッションの順番は、DB に入っている試合だけで数えているためです。プロフィールの「過去の試合を読み込む」で増やすと精度が上がります。
- 時間帯は日本時間固定です。
- 実際の Express・EJS・MongoDB での通し検証は、この環境ではできていません（npm が使えないため）。`npm test` のあと、プロフィールのボタンから `/insights/...` を開いて確認してください。
