# 公開運用と API キーのガイド

## まず知っておくこと（Riot の公式ルール）
- **開発キー**: ログインすると自動で発行される。24時間で失効する。**公開サイトでは使えない**。
- **個人用キー**: 製品（プロジェクト）を登録して申請する。個人利用向けで、**一般公開には使えない**。
- **本番用キー**: 一般公開する製品向け。レート制限が大きい。製品ごとに登録・審査が必要。
- 一般のプレイヤーに向けて公開するものは、API を使うかどうかに関わらず Developer Portal への登録が必要。

詳細は公式の Developer Portal（https://developer.riotgames.com/）と、そこにある API ポリシーを必ず確認してください。条件は変わることがあります。

## ローカルで使うだけの場合（今の状態）
- 開発キーのままで問題ありません。24時間ごとに再発行して `.env` の `RIOT_API_KEY` を書き換えて**保存**するだけです。v5.1 から再起動は不要です（401/403 を受けたとき `.env` を読み直します）。
- キーが失効している間、画面の上部に警告が出ます。保存済みのデータは見られます。
- 状態は `/healthz` で確認できます（`apiKey` が `valid` / `invalid` / `unknown`）。

## 他の人にも公開する場合のチェックリスト
1. Developer Portal で製品を登録し、本番用キーを申請する（審査待ちの間も、開発キーで一般公開してはいけません）。
2. 申請前に用意しておくもの
   - 動くサイト（このアプリ）と、説明できる機能の一覧
   - 非公式ツールである旨の表記（フッターに実装済み）と「このサイトについて」ページ（`/about`。**内容は雛形です。運営者情報や連絡先、実際のデータの扱いに合わせて必ず書き換えてください**）
   - HTTPS での配信（API キーを守るために必要）。キーをコードやリポジトリに含めない（`.env` は `.gitignore` 済み）
3. 承認されたら `.env` のキーを差し替え、必要なら `RATE_LIMIT_1S` / `RATE_LIMIT_120S` を設定する（設定しなくても、Riot が返すヘッダーから自動で学習します）。
4. リバースプロキシ（nginx など）の背後で動かすときは `TRUST_PROXY=1` を設定する（IP 制限が正しく働くため）。
5. `STRICT_ENV=1` を設定し、`.env` の変数名を正式名に統一する。

## 運用のコツ
- `npm run start:all` でサーバーとクローラーを1プロセスで動かすと、API の使用回数を1か所で数えられます。
- 別プロセスで動かす場合も、`RATE_SHARED` が有効（既定）なら MongoDB 経由で使用回数が合算されます。
- 終了は Ctrl+C か SIGTERM。クローラーと MongoDB 接続を閉じてから終了します。
