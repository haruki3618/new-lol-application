# 画面の「待つ・失敗する」場面の設計（シナリオ表）

「ユーザーが何を見て、何をすればよいか」を先に決めておくための表です。**実装の現状**の列は v6.7.0 時点で、文言は画面に出る実際のものです。変えたいところは「変更案」に書き込み、決まったらコードへ反映します。

## 原則
1. **黙って止まらない**: 待つ場面には、進んでいることが分かる表示（スピナー・進捗・件数）を出す
2. **失敗の理由を 1 文で**: 内部の文言（Riot / DB のエラー文）は出さない。原因が分かるなら「何をすればいいか」まで書く
3. **やり直せる**: 再試行できる失敗には「もう一度試す」を出す。入力は消さない
4. **古くても出せるものは出す**: 取得に失敗しても、少し前のデータがあれば注意書きつきで表示する（v6.7.0）

## 場面ごとの設計

| # | 場面 | 何が起きているか | 画面の表示（現状） | 次にユーザーができること | 変更案 |
|---|---|---|---|---|---|
| 1 | 戦績の同期ボタンを押した | 試合を Riot から取得中（数秒〜数十秒） | 上部のバーに「試合を取得中… 3 / 10」と進捗バー。完了で中身だけ差し替え（タブ・スクロールは保つ） | 待つ。他のタブは見られる | |
| 2 | 同期が失敗した | 429 / 5xx / 通信切断 | バーに理由を表示し、画面下にトースト（7 秒）。スピナーは消える | ページを再読み込みして再試行 | |
| 3 | Riot API が混んでいる（429） | 全体の枠が一杯 | 専用画面に「あと約 N 秒」のカウントダウンと「もう一度試す」 | 待つか、ボタンを押す | |
| 4 | Riot API が不調（5xx）でランキングを開いた | 上流の障害 | 最大 1 時間前のデータがあれば、「約 N 分前のデータを表示しています」の注意書きつきで表示。無ければエラー画面（502） | 時間をおく | |
| 5 | サモナー名が見つからない | Riot ID の打ち間違い | 「見つかりませんでした。Riot ID のスペルとタグを確認してください」。60 秒は同じ名前で API を使わない | スペル・タグ・リージョンを確認 | |
| 6 | Riot ID の形式が違う | 入力ミス（`#` が無いなど） | ブラウザの入力チェック「ゲーム名#タグの形式で入力してください」。入力は残る | 直して再送信 | |
| 7 | 遅延タブ（マスタリーなど）が読めない | 取得失敗 | タブの中に「読み込めませんでした」と「もう一度試す」。読み込み済みにはしない | ボタンを押す | |
| 8 | タイムライン／ビルドのボタンで失敗 | 取得失敗 | ボタンの下に理由。ボタンは残る（再試行できる） | ボタンをもう一度押す | |
| 9 | ライブゲームで「データ不足を取得」が一部失敗 | プレイヤーごとの取得で失敗 | 「一部を取得できませんでした（N 人）」＋トースト | 時間をおいて再度 | |
| 10 | 過去の試合の読み込みが失敗 | 取得失敗 | 理由を表示し、トースト。選択肢は操作可能に戻る | もう一度 | |
| 11 | 端末がオフライン | 通信できない | 画面下に「インターネットに接続されていません」（接続が戻るまで表示し、戻ったら「接続が戻りました」） | 接続を確認 | |
| 12 | API キーが失効している | サイト側の問題 | 画面上部に警告。保存済みの試合は見られる。API が必要な操作は 503 | 管理者が復旧するまで待つ（運用は `OPERATIONS.md`） | |

## 文言を変えるとき
- 利用者向けの文は `src/utils/httpError.js`（サーバー）と `src/public/js/app.js` の `errorText`（ブラウザ）に集まっています。**この 2 か所を直せば、ほぼ全画面に反映されます**。
- 文を変えたら `npm test`（`test/v661.test.js` / `test/v670.test.js` が主要な文言を確認します）。

## 新しい「待つ」画面を作るときの確認
- [ ] 待ち始めに何か動く（スピナー・スケルトン）
- [ ] 失敗したとき、理由と「次にすること」が出る
- [ ] 失敗しても入力・スクロール位置・開いているタブが残る
- [ ] 再試行できる（ボタン）
- [ ] 内部のエラー文を出していない（`userMessage(err)` を通す）
