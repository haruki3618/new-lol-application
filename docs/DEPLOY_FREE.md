# 無料で公開して、データを自動更新する手順（v6.4.1）

構成は次のとおりです。すべて無料枠で動かします（2026年10月時点の各社ドキュメントで確認した内容です。無料枠は変わることがあるので、申し込む前に各サービスの公式ページで最新の条件を見てください）。

| 役割 | 使うもの | 無料枠の主な制限 |
| --- | --- | --- |
| サイト（Node.js） | Render の Free web service | 15分アクセスが無いと停止し、次のアクセスで起動し直す（約1分）。月750時間まで |
| データベース | MongoDB Atlas の M0 | 容量 512 MB |
| 自動更新（クローラー・お気に入り追跡） | GitHub Actions | 公開リポジトリなら無料。1ジョブは最長6時間。定期実行は数分〜数時間遅れることがある |

## 0. 先に必ず読むこと（Riot API キー）

- 開発キーは **24時間で失効**し、**一般公開には使えません**。自動更新も、毎日キーを差し替えない限り止まります。
- 個人用キーも「個人利用向け」で、**一般公開には使えません**。本番用キーの審査待ちの間も、開発キー・個人用キーで一般公開してはいけません（Riot の Developer Portal の説明）。
- 一般公開するなら **本番用キー**（Developer Portal の「Register Project」から申請）が必要です。レート制限はリージョンごとに数えられます。
- そこで、進め方は2段階にします。
  1. **承認前（非公開）**: サイト全体をパスワードで守ったまま、自動更新を動かす。キーは、Developer Portal で個人用キーを申請して使う（開発キーと違い毎日の再発行は不要と報告されていますが、期限や条件はポータルで確認してください）。
  2. **承認後（公開）**: 本番用キーに差し替え、パスワードを外して公開する。

申請に必要なものは `docs/PRODUCTION_KEY.md` にまとめています。`/about` の内容は雛形なので、運営者情報や連絡先、実際のデータの扱いに合わせて書き換えてください。

## 1. GitHub にコードを置く

公開（Public）リポジトリにします。非公開のリポジトリだと、Actions の無料分は月の上限があり、15分おきのお気に入り追跡は収まらない可能性があります。キーはコードに入れず、後で Secrets に入れるので、公開しても漏れません。

1. GitHub で新しいリポジトリを作る（Public）。
2. zip を展開したフォルダで、次を実行する（`.env` と `node_modules` は `.gitignore` で除外済みです）。

```
git init
git add .
git commit -m "first commit"
git branch -M main
git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
git push -u origin main
```

3. `git status` で `.env` が含まれていないことを確認する。

## 2. データベース（MongoDB Atlas）

1. MongoDB Atlas に登録し、**M0（Free）** のクラスターを作る。リージョンは日本に近い Singapore を選ぶ（無料枠で選べるリージョンは限られます）。
2. **Database Access** で、ユーザーとパスワードを作る（パスワードは英数字だけにすると、接続文字列の記号の扱いで悩みません）。
3. **Network Access** で `0.0.0.0/0`（どこからでも）を追加する。Render と GitHub Actions は接続元の IP が固定ではないためです。そのぶん、**パスワードを長く推測されにくいものにする**ことが大事です。
4. **Connect → Drivers** で接続文字列を取り、データベース名を付ける。

```
mongodb+srv://<ユーザー>:<パスワード>@cluster0.xxxxx.mongodb.net/lol-analytics?retryWrites=true&w=majority
```

容量の目安: 1試合あたり約8 KB なので、`MAX_MATCHES=20000`（既定）で試合データが約150 MB、インデックスなどを入れても 512 MB に収まる見込みです（見積もりです。Atlas の画面で使用量を時々確認してください）。上限を超えるとデータを書き込めなくなるので、`MAX_MATCHES` を 40000 より大きくしないでください。

## 3. サイトを公開する（Render）

1. Render に登録し、GitHub と連携する。
2. **New → Blueprint** でこのリポジトリを選ぶ（`render.yaml` の内容で作られます）。
3. 値を聞かれる環境変数を入力する。

| 名前 | 値 |
| --- | --- |
| `RIOT_API_KEY` | Riot のキー |
| `MONGODB_URI` | 手順2の接続文字列 |
| `SITE_PASSWORD` | **承認前は必ず設定**（サイト全体が ID `admin` + このパスワードで守られます。公開するときに削除） |
| `WEBHOOK_SECRET` | お気に入り追跡の Webhook URL を暗号化して保存する秘密の文字列（`openssl rand -hex 32` などで作る長いランダム文字列）。**GitHub の Secrets（`watch.yml` 用）にも同じ値を登録**。変えると既存の登録を復号できなくなる |
| `WATCH_REGISTER_KEY` | （任意）設定すると、追跡の追加に登録キーが必要になる。公開後に枠を荒らされたくないときに |

4. デプロイが終わったら、`https://<サービス名>.onrender.com/healthz` を開き、`"db":"connected"` を確認する。
5. トップページを開く（最初の1回は起動に約1分かかります）。

`render.yaml` では `WATCH_INTERVAL_MIN=0`（サーバー内の巡回なし）にしています。無料のサービスは止まっている間は巡回できないため、お気に入り追跡は手順4の Actions が担当します。

## 4. 自動更新（GitHub Actions）

1. リポジトリの **Settings → Secrets and variables → Actions → New repository secret** で、次の2つを登録する。
   - `RIOT_API_KEY`
   - `MONGODB_URI`
2. （任意）同じ画面の **Variables** に `CRAWLER_REGION`（例: `jp`）と `MAX_MATCHES` を登録する。書かなければ `jp` と `20000` です。
3. **Actions** タブで、`crawler` を選び **Run workflow** で手動実行して、ログに `[Crawler] ... 試合を確認` が出ることを確認する。
4. 以降は自動です。

| ワークフロー | 動く時刻（UTC） | 内容 |
| --- | --- | --- |
| `crawler` | 6時間おき | 約5時間半ぶん試合を集め、事前集計も同時に更新する |
| `watch` | 15分おき | お気に入り追跡を1周確認して Discord に通知する（使わないなら `.github/workflows/watch.yml` を削除） |
| `keepalive` | 毎月1日 | 空のコミットを作る。公開リポジトリは60日間なにも更新が無いと、定期実行が自動で止まるため |

確認のしかた: 数時間後にサイトの `/tierlist` や、ホームの「保存済みの試合」の件数が増えていれば成功です。ティアリストは、1つのパッチで試合が数百件たまるまでは「データ不足」と表示されます。

## 5. 公開する（本番用キーが承認されたあと）

1. Render の環境変数 `RIOT_API_KEY` と、GitHub の Secret `RIOT_API_KEY` を、**どちらも**本番用キーに差し替える。
2. Render の環境変数 `SITE_PASSWORD` を削除して、再デプロイする。
3. `/about` に運営者情報と連絡先を書く。
4. 必要なら、`RATE_LIMIT_1S` / `RATE_LIMIT_120S` を設定する（書かなくても、Riot が返すヘッダーから自動で学習します）。

## うまくいかないとき

| 症状 | 原因と対処 |
| --- | --- |
| サイトが開くまで1分かかる | Render の無料枠は、15分アクセスが無いと止まります。仕様です。月750時間の範囲で、外部の死活監視サービスから定期的にアクセスして起こし続ける方法もありますが、サービス側の規約や無料枠の変更を確認してから使ってください |
| 画面の上に「APIキーが無効」と出る / Actions が 401・403 で失敗 | キーが失効しています。開発キーは24時間で切れます。個人用または本番用のキーを使い、Render と GitHub の両方を更新してください |
| Actions が実行されない | Actions が有効か、ワークフローが `main` ブランチにあるか、60日以上更新が無いか（`keepalive` が動いているか）を確認。定期実行は混雑時に数時間遅れることがあります。手動の Run workflow はすぐ動きます |
| Atlas に接続できない | Network Access に `0.0.0.0/0` があるか、接続文字列にデータベース名とパスワードが入っているかを確認 |
| 書き込みエラーが出る | Atlas の容量（512 MB）がいっぱいです。v6.5 からは `MATCH_TTL_DAYS`（既定30日）と `MAX_DB_MB`（既定400）で自動的に空きますが、足りなければ値を小さくするか、`npm run db:reset` で作り直してください。`npm run storage` で使用量を確認できます |
| ティアリストが空 | `crawler` がまだ試合を集めていない、または `CRAWLER_REGION` と、サイトで選んでいるリージョンが違います |

## 代替案: Oracle Cloud の Always Free（常時起動の VM）

サイトが止まらず、クローラーも `npm run start:all` で1プロセスに入れられるので、Actions は不要になります。ただし次の注意があります。

- 登録にクレジットカードが必要です（本人確認用）。
- Arm の VM は在庫不足で作れないことがあります。
- 無料枠が 2026 年 7 月に 4 OCPU / 24 GB から 2 OCPU / 12 GB に減ったと報じられています。無料枠の範囲を必ず確認してください。
- 使用率がずっと低いと、VM が回収されることがあります。

手順の概要: VM を作る → Node.js 22 を入れる → コードを置く → `.env` を書く → `pm2 start "npm run start:all" --name lol` で常駐させる → Caddy などで HTTPS にする（`TRUST_PROXY=1` を設定）。MongoDB は Atlas の M0 をそのまま使えます。
