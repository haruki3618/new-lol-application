# リリース前チェックリスト

デプロイ（`main` への push）の前に上から確認します。**毎回全部やる必要はありません**。変えた範囲に当たる節だけでも通してください。

## 0. いつも
- [ ] `npm ci && npm test` が通る（GitHub Actions の `test` も緑）
- [ ] `package.json` の `version` を上げた（`package-lock.json` の version も同じに）。静的ファイルの URL に `?v=` が付くので、上げ忘れると古い JS / CSS が最大 1 時間残る
- [ ] `CHANGELOG.md` に、何を・なぜ変えたかを書いた（「実装しなかったもの」と理由も）
- [ ] 数か月に 1 回: `src/services/ddragon.js` の `FALLBACK_VERSION` を、`https://ddragon.leagueoflegends.com/api/versions.json` の先頭の版に更新した（古いと、取得失敗時に新しい画像が出ない）
- [ ] `.env` や API キーをコミットしていない（`git status` と `git diff --cached` を見る）

## 1. 画面の確認（ローカルで `npm start`）
- [ ] トップから Riot ID で検索できる（`ゲーム名#タグ`）
- [ ] 間違った形式（`#` 無し）を入れると、入力を残したままエラーが出る
- [ ] 存在しない ID を入れると「見つかりませんでした」が出る
- [ ] プロフィールが描画される（概要 / チャンピオン / 分析 / LP の各タブ）
- [ ] 試合カードの開閉、タイムライン・ビルドのボタンが動く
- [ ] 「同期」の進捗が出て、完了後にタブ位置が保たれる
- [ ] チャンピオン一覧 → 詳細（ビルド・マッチアップ）
- [ ] ランキング（apex とダイヤ以下の両方）
- [ ] ライブ画面（ゲーム中でないときは 200 で「ゲーム中ではありません」）
- [ ] 追跡 `/watch`（登録・解除。Webhook はテスト用のものを使う）
- [ ] ライト／ダークの切り替え、スマホ幅（`docs/MOBILE_CHECK.md` の抜粋）
- [ ] ブラウザの開発者ツールのコンソールに、赤いエラーが出ていない

## 2. 失敗系の確認
- [ ] `.env` の API キーをわざと壊す → 画面上部に警告が出て、保存済みの試合は見られる。`/healthz` の `apiKey` が `invalid`
- [ ] ブラウザを機内モードにして操作 → 画面下に「接続されていません」。戻すと「接続が戻りました」
- [ ] 存在しない API を叩く（例: `/api/tab/x`）→ JSON で `error` と `requestId` が返り、画面のエラーは「エラー ID」付き。Logs に同じ ID の行がある
- [ ] MongoDB を止める → `/healthz` が 503 になり、サーバーのプロセスは落ちない（戻したら自動で復帰するか確認）

## 3. データ・設定を変えたとき
- [ ] スキーマ（`src/models/`）やインデックスを変えた → 起動ログにエラーが出ない。大きな DB では、インデックスの作成で起動直後に少し重くなることがある
- [ ] 集計の形を変えた → `npm run agg:rebuild` が必要か、警告の表示を確認
- [ ] 利用者の入力（クエリ・パス・フォーム）を受け取るルートを足した → 形の検証は `src/utils/validate.js` の関数を使う（正規表現をルートに書き写さない）。API 枠を使う操作は、さらに「検索を通った PUUID か」を DB で確認する
- [ ] 環境変数を足した・名前を変えた → `.env.example`・`render.yaml`・`docs/DEPLOY_FREE.md` を更新
- [ ] 依存パッケージを更新した → `npm ci` が通る、`npm audit` に重大な警告が無い

## 3.5 起動時の環境変数チェック
- [ ] 環境変数を足した・変えた → ローカルで `npm start` し、`[Config]` の警告（`注意:`）が出ていない
- [ ] わざと壊して止まるか確認（初回と、チェックを変えたときだけ）: `PORT=abc npm start` → 「起動できません」の一覧が出て終了コード 1（`echo $?`）
- [ ] 新しい設定を追加したら、数値なら `src/config/validate.js` の `NUMERIC_VARS` に範囲を追加する

## 4. デプロイ後（5 分）
- [ ] Render のデプロイが成功し、`/healthz` が `ok:true` / `db:"connected"`
- [ ] 本番でトップ → 検索 → プロフィールが開く
- [ ] ブラウザで強制再読み込みして、新しい `?v=` の JS / CSS が読まれている（開発者ツールの Network）
- [ ] GitHub Actions を 1 回手動実行（`watch` など）して緑

## 5. 戻すとき
- 直前の版に戻す: Render → Deploys → 前の成功したデプロイの Rollback
- データを変える変更（集計・インデックス）をしたときは、戻したあとに `/healthz` と主要画面を再確認

## CHANGELOG の書き方
```
## vX.Y.Z（一言で）
### 変更
- **何を**: なぜ必要だったか・どう直したか
### 実装しなかったもの
- **何を**: 見送った理由
### テスト
- 追加したテスト、実行できなかったもの（あれば正直に）
```
