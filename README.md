# LoL Analytics v6.11.0

OP.GG を参考にした、LoL の戦績解析アプリ（17 リージョン対応）。Riot 公式 API の LoL 向け機能を使っています。

## 起動手順
1. zip を展開する（新しいフォルダ推奨。これまでの変更をすべて含んだ完成形です）
2. これまで使っていた `.env` をフォルダ直下に置く（無ければ `.env.example` をコピーして編集）
3. 初回のみ `npm install`
4. `npm run start:all`（サーバー + クローラー）→ http://localhost:3000　※クローラー無しなら `npm start`

MongoDB が起動している必要があります。保存済みの試合はそのまま使えるので `db:reset` は不要です（v5.2 以降は、初回に事前集計が自動で作られます）。
v5.1 で `chart.js` を依存に追加したため、**展開後に必ず `npm install` を実行**してください（LP推移グラフを自前で配信します）。

## 画面と使っている API
| 画面 | URL | 使用 API |
|---|---|---|
| 検索・プロフィール | /summoner | account-v1, summoner-v4, league-v4（by-puuid）, match-v5 |
| 試合詳細（ルーン・スキル・ビルド） | プロフィール内 | match-v5（試合・タイムライン） |
| タイムライン分析（v6.2） | プロフィールの試合を開いてボタン | match-v5（タイムライン。1試合につき1回、30日キャッシュ） |
| マスタリー | プロフィール内 | champion-mastery-v4（上位・全件・スコア） |
| ライブゲーム（v6.1 で強化） | /live | spectator-v5（active-games）, league-v4, champion-mastery-v4（by-champion。10人分）。成績は自分の DB |
| ランキング | /ranking | league-v4（apex・entries/{queue}/{tier}/{division}） |
| サーバー状況 | /status | lol-status-v4 |
| チャンピオン統計・図鑑 | /champions, /champion/ID | Data Dragon ＋ 自分の DB |
| ティアリスト（v5.2） | /tierlist | 自分の DB の事前集計（追加の API なし） |
| プレイ傾向の診断（v6.0） | /insights/PUUID（プロフィールのボタン） | 自分の DB のみ（API なし） |
| アイテム | /items | Data Dragon |
| マルチ検索 | /multi | 上記の組み合わせ |

プロフィールのマスタリーは、タブを開いたときに初めて API を呼びます（開発キーの上限を節約するため）。

## 無料で公開する
`docs/DEPLOY_FREE.md` に、Render + MongoDB Atlas + GitHub Actions で無料公開・自動更新する手順があります。一般公開には Riot の本番用キーが必要です（承認前は `SITE_PASSWORD` でサイトを守ってください）。

## v6.8.0 の変更（起動前に止める・失敗の原因を追える）
- **起動時の環境変数チェック**: キー・接続先の未設定や貼り間違い（前後の引用符・空白）、地域の綴り違い、数値でない設定を、DB に接続する前に検出して終了コード 1 で止める（Render ではデプロイ失敗で通知）。
- **エラー処理とログ**: async ルートの例外を必ず受け止める。全リクエストに ID を付け、エラー画面の「エラー ID」とログの `req=` を一致させる。ログに Riot API の呼び出し先・プレイヤー・試行回数を残し、API キー・Webhook・DB のパスワードは伏せる。未処理の例外が 1 分に 5 回起きたら終了して再起動に任せる。詳細は `CHANGELOG.md`、運用は `docs/OPERATIONS.md`。

## v6.7.0 の変更（障害に強く・つまずきにくく）
- Riot API が混雑・不調（429 / 5xx）のとき、1 時間以内の古いデータがあればそれを出す（ランキングは注意書きつき）。ランクは LP の記録に使うので対象外。再試行にジッター。`/healthz` に `cache`（ヒット率・古い値を返した回数）。
- 同期・履歴・ライブの失敗と、オフラインを画面下のトーストで知らせる。`prefers-reduced-motion` に対応。
- `Match` のインデックスを 2 つ追加（チャンピオン別ページ・パッチ一覧）。`/api/sync` などで Riot のエラー文がそのまま返っていたのを修正。
- 計算ロジックに JSDoc（`src/types.js`、`jsconfig.json`）。
- 運用の文書: `docs/OPERATIONS.md`（キーの台帳・週次の見回り）、`docs/RELEASE_CHECKLIST.md`、`docs/UX_SCENARIOS.md`、`docs/MOBILE_CHECK.md`。詳細は `CHANGELOG.md`。

## v6.6.1 の変更（不具合の修正・API 枠の保護）
v6.6.0 のコードを読み直して見つかった不具合と抜けを直した版です。画面・機能の追加はありません。
- **壊れた Cookie で全ページが 500 になる**問題を修正（リージョンの Cookie に不正な `%xx` があると例外になっていた）。
- **API 枠の保護**: `/api/live-fill`（ライブの「データ不足を取得」）と `/api/tab`（マスタリー）も、同期・履歴と同じく「検索を通った PUUID」だけ受け付ける。存在しない Riot ID の検索は 60 秒だけ覚え、同じ入力で API を使わない。
- **クローラーの空回り**: 起点をすべて確認し終えると、10 秒おきに順位表の API を呼び続けて低優先の枠を使い切っていた。確認済みを忘れて 5 分待ってからやり直すようにした。
- **エラー表示**: 想定外のエラー（DB の例外など）の内部文言を画面・JSON に出さない。Riot の 401/403（サイトの API キーの問題）は利用者には 503 で返す。`/api/tab` のエラー文はエスケープする。再試行できるエラー画面には「もう一度試す」を出す。
- **静的ファイルのキャッシュ**: JS / CSS の URL に `?v=バージョン` を付け、更新後に古いファイルが最大 1 時間ブラウザに残らないようにした。
- **`npm run agg:rebuild`**: 期限・容量で削除済みの試合ぶんの集計が失われるときは、`-- --yes` を付けないと実行しない（作り直しは「いま保存されている試合」だけから集計するため）。
- そのほか: `/search` に配列が渡されても落ちない／`/` の描画エラーで応答が止まらない／お気に入り追跡の登録 IP の記録は `WEBHOOK_SECRET` があれば HMAC／Discord 通知はリダイレクト先へ送らない。
- テスト: `test/v661.test.js` を追加。全テンプレートの構文チェックを含む。

## v6.6.0 の変更（API・運用の保護、UI・アクセシビリティ）
- **同期・履歴**: 検索を通った PUUID だけ受け付ける。履歴の読み込みは IP ごとに 1 日 10 回まで（`HISTORY_PER_DAY`）。同期は「開始」と「進捗確認」で別々の枠（`SYNC_START_PER_MIN`）。
- **ランク・マスタリー**: 取得に失敗したとき「未ランク」「データなし」と表示せず、「取得できません」と出す。失敗はキャッシュしない。
- **運用**: 未処理の例外・Promise 拒否でプロセスが落ちないようログを出して続行。追跡は巡回ごとに「確認中」の印を取って二重通知を防ぐ。`TRUST_PROXY` 未設定でプロキシ経由のアクセスを検出したら警告。Riot API の枠の確認で MongoDB の読み取りを減らした。
- **画面**: 通信失敗時にボタン・タブが戻り再試行できる／同期完了や「もっと見る」でページ全体を読み直さない／タブを URL の `#` に保存／入力を間違えても今の画面と入力を残す／試合カードをキーボードで開閉／スペル・ルーン・アイテムの代替テキスト／文字サイズの引き上げ／favicon・description・OGP／横スクロールメニューの端のぼかし／ライブの経過時間が進む／429 画面に待ち時間と再試行ボタン／ライトテーマ（OS の設定に従う。ナビの ◐ で手動切替）。
- **CSP**: `style-src` から `'unsafe-inline'` と Google Fonts を除去（フォントはシステムフォント）。詳細は `CHANGELOG.md`。

## v6.5.1 の変更（セキュリティ・保守）
- `/watch`: 追跡中のプレイヤー名を既定で非表示（`WATCH_PUBLIC_LIST=1` で公開）。追加に登録キー（`WATCH_REGISTER_KEY`）を設定可能。追加・解除は IP ごとに 1 時間あたりの上限あり。Webhook URL は `WEBHOOK_SECRET` で暗号化して保存。上限件数を超えないよう登録後にも数え直す。
- `/api/timeline` `/api/detail`: 保存済みの試合・参加者だけ受け付ける（任意の試合 ID で Riot API の枠を使わせない）。ユーザー操作が使える API の割合を 0.95 → 0.85 に。
- IP 制限をスライディングウィンドウ方式に変更（境目で 2 倍通る問題を解消）。
- CSP から `script-src 'unsafe-inline'` を除去（インライン `onerror` と LP データの inline script を廃止）。
- GitHub Actions に `test.yml`（push / PR で `npm test` と `npm audit`）を追加。
- デュオ・レポート・診断の画面に、試合の保存期間（既定 30 日）の注記を追加。

## v6.4 の新機能
- **リージョン選択**: 検索欄の横で選べます。既定は `.env` の `DEFAULT_REGION`（書かなければ JP）。クローラーは `CRAWLER_REGION` の1リージョンを集め、統計・ティアリストはリージョンごとに別集計です。初回起動のとき、事前集計を1回だけ自動で作り直します。
- **おすすめビルド**（`/champion/Ahri`）: ロール別のルーン・スペル・ブーツ・コアビルド。ルーンページ全体は v6.4 以降に保存した試合だけが対象です。
- **対面**: チャンピオン詳細の対面表と、2体の直接対決 `/matchup?champ=Ahri&vs=Zed`。

## v6.3 の新機能
- `/duo` デュオ / 対戦比較（保存済みの試合だけを使用。API 不要）
- `/watch` お気に入り追跡 + Discord 通知（`WATCH_INTERVAL_MIN` で間隔を設定。サーバー起動中に巡回）
- `/report` 週間 / 月間レポート（保存済みの試合と LP 履歴を使用）

## 含まれない API
- TFT / VALORANT / LoR: LoL 以外のゲームなので対象外
- tournament-v4 / tournament-stub-v4: 本番用キーが必要
- summoner-v4 の `/me`、account-v1 の `/me`: ログイン連携（RSO）が必要

## コマンド
- `npm start` … サーバー起動
- `npm run start:all` … サーバーとクローラーを1つのプロセスで起動（おすすめ。APIの使用回数を1か所で数えられる）
- `npm run crawler` … クローラーだけ別プロセスで起動（使用回数は MongoDB 経由でサーバーと合算される）
- `npm test` … 自動テスト
- `npm run db:reset` … 保存済みの試合を削除（LP推移は残す）
- `npm run agg:rebuild` … 事前集計を保存済みの試合から作り直す（削除済みの試合ぶんが失われるときは `-- --yes` が必要）

## v5.1 で変わったこと（安定化）
詳しくは `CHANGELOG.md`、公開運用は `docs/PRODUCTION_KEY.md` を見てください。
- API の使用回数をプロセス間で共有。上限は Riot のヘッダーから自動で学習

- IP ごとのアクセス制限、セキュリティヘッダー、gzip 圧縮、Chart.js の自前配信
- アカウント・名前の解決・ランキングを MongoDB に永続キャッシュ
- 開発キーの失効を検知して画面に警告。`.env` を書き換えて保存すれば再起動なしで復旧
- 終了時の後片付け、`/healthz`、自動テスト（32件）
